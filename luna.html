תוכנית למידה: מ-Team Lead ל-Staff/Principal Engineer

1 יסודות מערכות מבוזרות (שבועות 1-6)

מטרה: עומק ארכיטקטוני - הבסיס לראיונות Staff ולתפקיד עצמו.
  • 📖 ספר: Designing Data-Intensive Applications - פרקים 1-9 (replication, partitioning, transactions, distributed systems)
  • 🎥 לחיזוק: קורס System Design באתר educative / סרטוני system design ביוטיוב
  • ✍️ תרגול: לתכנן על נייר 3 מערכות מוכרות (URL shortener, WhatsApp, Uber) - 45 דקות כל אחת, כמו בראיון
  • 🏢 בעבודה: לכתוב design doc מסודר אחד על מהלך ארכיטקטוני אמיתי בצוות
תוצר מדיד: design doc אחד כתוב + יכולת לעבור mock של system design בסיסי
השבוע הראשון (טיול למינכן) - רק קריאה קלה, בלי לחץ.

2 עומק AI - להפוך לסמכות (שבועות 4-12, חופף)

מטרה: להיות האדם שכל הארגון מתייעץ איתו על AI.
  • 📖 נושאים: LLM evals, RAG architectures, אופטימיזציית latency/cost, observability ו-debugging של סוכנים, guardrails
  • 🛠️ פרויקט: לבנות framework פנימי ל-evals של הכלים האגנטיים שאתה מפתח
  • 🎤 להעביר הרצאה פנימית אחת ב-Fireblocks על agentic workflows / MCP
תוצר מדיד: framework evals עובד + הרצאה פנימית

3 השפעה רוחבית ונראות (שבועות 8-20)

מטרה: impact מעבר לצוות - מה שמגייסים ומקדמים באמת בודקים.
  • ✍️ לכתוב 3 פוסטים טכניים (LinkedIn / בלוג) - אחד על MCP, אחד על evals, אחד על system design
  • 🤝 תרומה ל-open source - ה-ecosystem של MCP הוא מקום טבעי להתחיל
  • 🎤 להגיש הצעה להרצאה במיטאפ/כנס (למשל: AI agents in production)
תוצר מדיד: 3 פוסטים מפורסמים + PR אחד ממוזג ב-open source

4 מוכנות לראיונות Staff (שבועות 16-24)

מטרה: להגיע לראיונות חדים, לא להיתפס לא מוכן.
  • 🧩 רענון algorithms/data structures - רשימה ממוקדת (כ-75 בעיות נבחרות, לא 300)
  • 🎯 תרגול system design interviews - עם חבר או דרך פלטפורמות mock
  • 📝 להכין "סיפורי Staff": 5-6 סיפורים מובנים על מהלכים ארכיטקטוניים שהובלת, בפורמט STAR, עם דגש על trade-offs והשפעה ארגונית
תוצר מדיד: 2 mock interviews שעברו בהצלחה
